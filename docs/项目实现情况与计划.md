# 商品管理系统 — 实现情况与后续计划

> 更新时间：2026-09-10  
> 前端：`product-manage-web`（RuoYi-Vue 3.9.2 / Vue 3 + Vite + Element Plus）  
> 后端：`product-manage-system`（RuoYi 3.9.2 / `ruoyi-pms`）  
> 设计稿：Figma Make [GoodsMgr 便利店/快消进销存 + 货架墨水屏](https://www.figma.com/make/yM36X1dUYtFxpCyJsr70Ny/生成设计稿)

本文对照设计稿 8 个业务模块、后端实际菜单，以及已经落地的三期开发，列出**已做好**、**半成品**、**没做完**，并给出下一期计划。

---

## 1. 一句话结论

核心进销存链路（商品、分类、供应商、进货、库存调整、销售、物流对账、墨水屏绑定、看板、报表、业务设置）**已经接通真实接口，可以日常使用**。

还没收口的主要是：

1. 后端已有、前端缺失的 **物流商管理页**（菜单点进去会 404）
2. 墨水屏 **设备端联调 / 模板预览**（管理端接口有了，真机协议未在本仓库落地）
3. 台账类单据 **不能改、不能作废**（进货、销售只有新增）
4. 早期 `goods/*` 页面和 `sql/goods_phase*.sql` **已经过期**，不要再执行
5. 设计稿视觉和交互仍是若依列表页风格，**没有按 Figma 像素还原**（这是当时明确选择）

## 4. 已经做好的（按功能拆）

### 4.1 首页 / 经营看板

已替换若依默认「技术选型」首页，首页和「经营看板」共用同一套页面。

已接接口：

- 看板 KPI：`GET /pms/dashboard`（商品数、预警、零库存、离线墨水屏、待对账/未结清物流、今日营业额、营收预警文案）
- 本月库存与进货成本：`GET /pms/report/overview?range=month`
- 本月/本周营业额与环比：`/pms/report/turnover`、`/turnover/compare`
- 年度趋势、本周趋势：`/pms/report/turnover/trend`
- 热销 TOP 5：`/pms/report/turnover/rank`
- 最近进货：`GET /pms/purchase/list`
- 通知数据：预警商品、离线设备、未结清物流

页面能力：KPI 卡片、年度柱状图（按月/周/日）、本周折线、通知跳转、热销进度条、最近进货表。

### 4.2 商品信息

- 列表、搜索（名称 / 分类 / 厂家）、库存预警 / 零库存 Tab
- 新增、编辑、删除、批量删除、导出
- 批量编辑、批量同步墨水屏
- KPI 接看板数据

缺：Excel 导入、打印价签、商品图库（设计里如果有也未做）。

### 4.3 商品分类

- 名称、排序、启停、新增 / 修改 / 删除
- 商品页、报表页用 `optionselect` 下拉

### 4.4 供应商

- 列表、新增、修改、删除、导出、状态开关
- 详情：供货商品 + 进货记录

### 4.5 进货入库 / 库存流水

共用 `src/views/pms/inventory/index.vue`：

- 进货台账：新增进货（加库存、写流水）、导出、按厂家和时间筛选
- 库存流水：入库 / 盘点 / 损耗 / 调拨 / 销售 / 建档
- 库存调整：盘点、损耗、调拨（`PUT /pms/stock/adjust`，`afterQtyTarget`）
- KPI：本月进货金额/批次、预警、零库存

缺：进货单修改 / 作废 / 冲红；采购收货多商品一行单据（当前是一单一品）。

### 4.6 销售出库

- 列表、筛选、出库（扣库存、写流水）、详情、导出
- 库存不足时后端会拦

缺：改单、退货、作废、POS/扫码、多商品一单。

### 4.7 物流对账

- 账单列表、新增、对账、结清、批量对账、导出
- 费用统计（按月 / 按物流商）
- KPI：总费用、已结清、待对账金额和单数

缺口见第 5 节。

### 4.8 墨水屏（管理端）

- 设备列表、绑定商品/货架、解绑、刷新、重启、批量同步
- 在线/离线、电量、同步日志
- 后端另有匿名设备接口：`POST /pms/eink/heartbeat`、`GET /pms/eink/content/{sn}`、`POST /pms/eink/ack`
- 模板读写：`GET/PUT /pms/device/template`（与业务设置同一张 `pms_setting`）

前端 `getDeviceTemplate` / `saveDeviceTemplate` 已写在 `src/api/pms/device.js`，**设备页没有调用**，展示开关实际在业务设置里改。

### 4.9 报表统计

- 周期：日 / 周 / 月 / 年 / 自定义
- 经营概览：营收、进货成本、毛利、毛利率 + 趋势图 + 热销 + 供应商占比
- 进货明细、库存台账、成本统计、供应商、营业额（含对比、排行、明细）
- 导出：`POST /pms/report/export/{reportType}`

注意：概览里的「毛利」= 期间营业额 − 期间进货成本，**不是已售商品的真实销售成本**。

### 4.10 业务设置

- 库存预警阈值、营收下限/上限
- 墨水屏同步频率：实时 `1` / 5 分钟 `300` / 15 分钟 `900` / 手动 `0`
- 字体样式；名称/规格/售价固定展示；简介/库存/厂家可开关
- 操作日志：系统 `monitor/operlog` 最近 8 条（需有日志权限）

### 4.11 若依底座（不重做）

登录、验证码、用户/角色/菜单/字典、部门岗位、操作日志、定时任务、代码生成等沿用若依，不在业务范围内。

## 5. 没做完 / 半成品（详细）

### 5.1 必须补的缺口

| 项 | 现状 | 影响 |
|---|---|---|
| 物流商管理页 | 后端菜单 `pms/carrier/index`，接口 CRUD 齐全；前端没有页面 | 点「物流商」404 |
| 物流商数据源 | 对账页用本地写死的 `GOODS_CARRIER`（顺丰/德邦/中通/京东），字典类型还叫 `goods_carrier` | 和 `pms_carrier` 表两套数据，新增物流商对账页选不到 |
| 过期 SQL / 旧页面 | `sql/goods_phase1.sql`、`goods_phase2.sql` 仍是 `goods:*` 权限和 `goods/...` 组件；`src/views/goods/*` 是一期遗留 | 再执行会插冲突菜单或双菜单；不要当正式脚本 |
| 墨水屏设备端 | 心跳 / 拉内容 / 回执只在后端 | 没有模拟器或硬件联调页，货架屏不会自己亮 |
| 墨水屏模板预览 | 设置里只能开关字段，没有「价签长什么样」的预览 | 改完设置看不到效果 |

### 5.2 业务闭环缺口

| 项 | 现状 | 建议 |
|---|---|---|
| 进货单改/作废 | 只有 `POST /pms/purchase` | 至少做「作废并回滚库存」 |
| 销售单改/退货 | 只有 `POST /pms/sale` | 退货入库或作废回滚 |
| 一单多商品 | 进货、销售都是一单一 SKU | 便利店真实进货往往一批多个商品 |
| 商品导入 | 只有导出 | 上线补货很痛 |
| 报表毛利口径 | 用期间进货成本近似 | 应用加权/批次成本算已售成本 |
| 设置页操作日志 | 没有按 PMS 模块过滤，也没有独立表 | 至少按 title 过滤「商品/进货/墨水屏/物流/销售/设置」 |
| 首页通知下钻 | 只跳到模块列表，不带 `stockStatus=warning` 等 query | 点通知应直接落到对应筛选 |

### 5.3 设计稿有、当前弱的交互

这些不是「不能用」，而是和 Figma 差一截：

- 首页系统通知文案、图表对比数字还可以再贴设计
- 报表默认是多 Tab，设计是单页（营收 KPI + 趋势 + TOP5 + 供应商）；概览 Tab 已接近，其它 Tab 仍是后台报表
- 设置页没有「价签预览卡」
- 墨水屏页没有模板编辑入口（权限 `pms:device:edit` 闲置）
- 没有移动端适配（设计若有也未做）
- 没有打印价签 / 导出 PDF

### 5.4 工程与质量

| 项 | 现状 |
|---|---|
| PMS 自动化测试 | 前端无单测/E2E；后端未见针对 pms 的用例 |
| 非 admin 角色 | 菜单权限 SQL 已拆按钮，但没有配「店长/库管/财务」现成角色 |
| 首页权限 | 首页会并发打报表/进货/设备/物流接口；非超管可能弹一串 403 |
| 中文文件编码 | 部分工具改中文 Vue/SQL 会把汉字打成 `?`，后端 `pms.sql` 在部分环境下已是乱码，**以库里已执行的菜单为准** |
| 环境文件 | `.env.development` / `.env.staging` / `.env.production` 有改动，提交时不要带密钥 |

## 8. 后续计划

原则：先补会堵人的缺口，再补业务闭环，最后再做体验和设备。

### 第四期（建议 1 周）— 收口菜单和脏数据

目标：菜单都能点开，物流商只保留一套数据，旧文件不再误导。

1. 新增 `src/views/pms/carrier/index.vue` + `src/api/pms/carrier.js`，对上 `/pms/carrier`
2. 物流对账的物流商下拉改为 `optionselect`，写入 `carrierId`，去掉 `GOODS_CARRIER` 写死列表
3. 删除或归档 `src/views/goods/**`、`sql/goods_phase*.sql`，文档里写明只认 `pms.sql`
4. 首页通知跳转带筛选参数（预警商品、离线设备、未结清物流）
5. 设置页操作日志按 PMS 模块 title 过滤
6. 看板在部分报表接口 403 时静默降级，避免一串报错

验收：admin 点开商品管理下每一个菜单都不 404；对账页能选到库里的物流商。

### 第五期（建议 1～1.5 周）— 单据闭环

目标：进销存可以纠错，铺货可以批量导入。

1. 进货作废（回滚库存 + 写冲正流水）
2. 销售退货 / 作废（回加库存）
3. 商品 Excel 导入（编码、名称、规格、分类、厂家、进价、售价）
4. （可选）进货/销售支持一单多明细，工作量明显更大，可单独开一期

验收：错误进货、错误销售能纠正；一份 Excel 能进一批商品。

### 第六期（建议 1～2 周）— 墨水屏真用起来

目标：改价后能在预览或模拟器里看到价签，设备能心跳和回执。

1. 设备页或设置页加价签预览（按 `showName/Spec/SalePrice/Intro/Stock/Supplier` 渲染）
2. 做一个简易模拟器页：输入 SN，调 `heartbeat` / `content` / `ack`
3. 和真实墨水屏协议对齐（电量、固件、超时离线）
4. 同步频率按设置生效（现在字段能存，定时任务/设备轮询要确认后端是否在跑）

验收：改售价 → 点刷新 → 预览或模拟器内容变；断心跳后看板离线数增加。

### 第七期（建议按需）— 报表口径和体验

1. 毛利改成「销售收入 − 已售成本」，成本用移动加权或批次
2. 报表导出字段和页面列对齐，概览导出不要只导库存 KPI
3. 补店长 / 库管 / 财务角色和菜单
4. 关键页加空态、筛选记忆、看板自动刷新
5. 适量 E2E：登录 → 新品 → 进货 → 出库 → 看板数字变化

### 不建议再做的

- 不要把业务再迁回 `goods/*` mock
- 不要为了「像 Figma」重写 Layout / 登录 / 侧边栏
- 不要同时维护两套菜单 SQL

## 9. 建议的下一期执行顺序

如果只排最近两周，按这个做：

```
P0  物流商页面 + 对账页改接 carrier 接口
P0  清理 goods 遗留页面和过期 SQL
P1  首页通知带筛选；看板 403 降级
P1  设置日志过滤
P2  进货作废、销售退货
P2  商品导入
P3  墨水屏预览 + 模拟器
```

做完 P0，这个项目在「菜单完整、主数据一致」上才算收口；P2 之后才适合给店里试用进销存；P3 之后墨水屏才不是只在后台点按钮。
